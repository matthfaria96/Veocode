# Veocode

Workspace visual para usar várias contas de IA (Claude, DeepSeek, modelos locais…) em projetos diferentes, controlar o nível de acesso de cada uma e enxergar tudo o que elas fazem na máquina.

**Fase atual: Painel (todos os projetos e até 4 chats lado a lado).** Projetos são pastas de verdade (árvore, arquivos e mudanças no disco ao vivo). O Raio-X lê a máquina: tamanho dos caches das IAs e dos gerenciadores de pacote, o que o Claude Code instalou (lido dos históricos em `~/.claude/projects`), VMs e containers (Docker, Lima, UTM, Parallels, VirtualBox) e os agentes de IA rodando com os processos filhos e portas. Limpar sempre move para a Lixeira; remover pacotes só copia o comando, nada é executado; encerrar só vale para processos iniciados por um agente. As **Contas** também são reais: cada conta do Claude é uma pasta separada do Claude Code (`CLAUDE_CONFIG_DIR`), com plano, uso por dia e modelos lidos dos históricos; o login é feito pelo próprio Claude Code num terminal aberto pelo Veocode. DeepSeek e APIs compatíveis com OpenAI guardam a chave no chaveiro do sistema e mostram saldo e modelos; o Ollama é detectado no endereço local. **Skills e MCP** também são lidos do disco: skills, comandos e agentes de cada conta, plugins instalados (com as skills e MCP que trazem, e se valem só para um projeto) e servidores MCP de conta, locais e de `.mcp.json` dos projetos. Dos MCP aparecem só o comando, o tipo e os *nomes* das variáveis de ambiente; valores de chaves e tokens nunca são lidos para a tela. No macOS o sistema pode pedir acesso à pasta Documentos na primeira leitura, porque alguns plugins e servidores ficam lá. O **nível de acesso** agora vale de verdade para o Claude Code: o Veocode traduz o nível (e os ajustes de cada item: Permitido, Pergunta ou Bloqueado) em regras de permissão e grava em `.claude/settings.local.json` do projeto, que o Claude obedece (bloqueio sempre vence). Ele grava só as regras dele, guarda o que havia antes e desfaz exatamente isso; avisa se alguém mexer no arquivo por fora e mostra regras de outros arquivos que deixam passar sem perguntar. "Abrir o Claude aqui" abre o Terminal na pasta do projeto com a conta dele. Os **eventos do agente** também são reais: o Veocode lê ao vivo os históricos que o Claude Code grava em `projects/` de cada conta (só leitura, nada muda na configuração dele) e cada passo vira a mesma animação da demo: o cursor da conta vai até o arquivo, a árvore se abre e marca o que foi lido, buscado, editado ou criado, o editor abre o arquivo alterado, os comandos e o fim da saída aparecem no Terminal e a conversa (pedidos, respostas e passos) aparece no painel do agente. Subagentes ganham cursores próprios. Ao abrir o projeto, os últimos 60 passos das sessões das últimas 24 h aparecem como histórico. O **chat** agora funciona dentro do Veocode: com conta do Claude, o pedido vai para o próprio Claude Code rodando sem terminal (`claude -p` com entrada e saída em stream-json), na pasta do projeto, com a conta do projeto e com o nível de acesso indo junto (`--permission-mode` e `--settings` com as regras), mesmo que as regras nunca tenham sido gravadas no projeto. O que o nível manda perguntar aparece como cartão com Permitir e Recusar; o texto chega aos poucos; o botão de parar interrompe a resposta; "Nova conversa" começa uma sessão nova; e os passos (ler, editar, comandos) seguem aparecendo pela mesma animação dos eventos reais. Com DeepSeek, APIs compatíveis com OpenAI ou Ollama, o chat agora também trabalha na pasta: o Veocode oferece ao modelo seis ferramentas (listar pastas, ler arquivo, buscar texto, escrever arquivo, trocar um trecho e rodar comando) e executa cada pedido dele, rodada após rodada, até a resposta final. O nível de acesso vale do mesmo jeito: Permitido roda direto, Pergunta mostra o cartão com Permitir e Recusar (com o conteúdo, o trecho antes e depois ou o comando) e Bloqueado nem roda, e o modelo fica sabendo o motivo. Os comandos são separados por tipo (instalar pacotes, `git push`, rede, VMs) e o bloqueio de qualquer parte vence; no nível Pergunta, comandos só de leitura (`ls`, `git status`, `cat`…) rodam sem perguntar; escrever em `.claude/` sempre pergunta; arquivos de segredo (`.env`, chaves) seguem a regra de segredos; e as ferramentas de arquivo nunca saem da pasta do projeto. Comandos param em 2 minutos ou no botão de parar. Cada passo aparece na mesma animação (cursor, árvore, editor, Terminal e Atividade). Modelo que não aceita ferramentas volta a ser só conversa, com um aviso. O clipe manda junto o arquivo aberto (até 60 KB). As **conversas anteriores** de cada projeto ficam no botão de relógio do painel do agente: as sessões do Claude Code desta pasta (de todas as contas, abertas pelo chat, pelo Terminal ou pelo editor), com o título que a sessão tem (o nome dado com /rename, o gerado pelo Claude ou o primeiro pedido), o último pedido, a conta, a origem e quando mexeu; e as conversas com DeepSeek, OpenAI e Ollama, que o Veocode agora guarda em `chats/<projeto>/` na pasta de dados do app (com as chamadas de ferramenta). Clicar retoma: o fim da conversa volta para o painel e para a Atividade, e o próximo pedido continua dela (o Claude com `--resume`, na mesma sessão; a API com o histórico guardado). Conversas de outra conta aparecem com cadeado: é preciso trocar a conta do projeto antes. Os históricos do Claude são só lidos. Fechar o Veocode fecha os Claudes abertos pelo chat. O **Inventário** junta numa lista só tudo o que as IAs instalaram ou usam neste computador: agentes rodando agora, plugins, skills, comandos e agentes, servidores MCP, programas que o Claude Code instalou, VMs e containers e caches. Cada linha diz para qual projeto vale (a conta inteira, uma pasta, ou o computador todo; pastas que não estão no Veocode aparecem como "fora do Veocode"), se está ligado ou rodando e quanto pesa: CPU e memória do que roda agora (cada conversa aberta do Claude liga a sua cópia de cada servidor MCP, e o Veocode acha essas cópias entre os processos filhos dos agentes), o tamanho no disco dos plugins e caches, e os tokens de cada skill (o nome e a descrição entram em toda conversa; o resto só quando a skill é usada). Escolhendo um projeto, a lista mostra só o que vale nele e o "contexto fixo": quantos tokens as skills ligadas ocupam antes de você escrever qualquer coisa. Tirar nunca apaga de vez: skills, comandos e agentes vão para a Lixeira (no macOS pelo próprio sistema, sem pedir para controlar o Finder); plugins são ligados, desligados ou removidos e servidores MCP removidos pelo próprio Claude Code (`claude plugin …`, `claude mcp remove`), sempre com confirmação antes de remover. Skills que vieram do claude.ai e MCP que vêm de plugins dizem onde tirar. Programas instalados só copiam o comando de remoção. O que está dentro da pasta de um projeto (`.claude/skills`, `.mcp.json`) avisa que o arquivo do projeto muda. A **Ajuda** fica no botão de interrogação acima de Ajustes (ou F1, ou ? fora de campos de texto) e abre já no tópico da tela em que você está: começo rápido, uma página por tela (Mapa, Projetos, Contas e IAs, Inventário, Raio-X, Skills e MCP), nível de acesso, chat e conversas, e um glossário dos termos. Cada página tem uma ilustração animada da tela (SVG com as cores do tema, sem capturas e sem dados pessoais), o que ela mostra, o que dá para fazer e o que é bom saber, e um botão para abrir a tela. Setas trocam de tópico. Os textos ficam em `src/help/topics.ts` e os desenhos em `src/help/Scenes.tsx`. Os **Ajustes** (engrenagem no fim do menu lateral) escolhem o estilo dos ícones e das animações por cartões com prévia ao vivo, e valem na hora. Ícones **detalhados** (o padrão): pastas com volume e cor conforme o papel (src azul, testes verdes, assets rosa, docs verde-água, scripts amarelos, `.git` e `.claude` laranja, `node_modules`/`target`/`dist` cinza), arquivos como folhas com a etiqueta do tipo (TS, JS, RS, CSS, HTML, PY, IMG, NPM…) e cada projeto como uma pasta com cor própria e a sigla da tecnologia (Rs, TS, Py…). São desenhos próprios em SVG (`src/components/icons.tsx`), não ícones da Apple. **Minimalistas**: os traços finos de antes. Animações **reduzidas** tiram laços e deslizes do app inteiro. A tela também mostra onde ficam a configuração e os dados do app (com botão para abrir a pasta) e os atalhos. Os ajustes ficam em `settings.json` na pasta de configuração (`src-tauri/src/settings.rs`); valor estranho no arquivo volta ao padrão em vez de travar. O **Chat livre** (dois balões no menu lateral) é uma conversa fora de qualquer projeto, para tirar dúvidas, escrever e pensar junto, com a conta que você escolher no topo (Claude, DeepSeek, OpenAI-compatível ou Ollama). Usa a mesma máquina do chat dos projetos com o id especial `livre` (`src-tauri/src/livre.rs`, `src/livre.ts`, `src/views/Livre.tsx`): o Claude roda sempre na pasta própria `chat-livre/` da pasta de dados do app, no modo normal de conversa (não no de plano) e com instruções extras (`--append-system-prompt`). Não há mais modos: ele conversa normalmente e, quando a pergunta é sobre o computador, lê a pasta pessoal, que entra sempre como pasta extra (`--add-dir`; nas APIs, vira a raiz das ferramentas). O selo de permissão na caixa de mensagem escolhe o nível (`freeLevel`: Leitura, o padrão, que lê arquivos e roda comandos de leitura como `ls` sem perguntar, com os que mudam algo (`rm`, `mv`, `touch`, `chmod`, `kill`…) bloqueados e editar arquivos bloqueado; Sugerir; Editar; Total), compilado pelas mesmas regras dos projetos; pesquisar na internet nunca pergunta. Em qualquer nível, pastas de credenciais (`.ssh`, `.aws`, `.gnupg`, `.kube`, `.docker/config.json`, `.config/gh`, `.config/gcloud`, `.netrc`, `.npmrc`, chaveiro, cookies e a configuração do Veocode) e arquivos `.env`, `.pem`, `.key` e `id_rsa*` da pasta pessoal ficam bloqueados, e abrir páginas pede aprovação em Leitura e Sugerir, para nada lido no computador sair num link. A busca das APIs para em 20 mil arquivos ou 20 s. Os passos (o que ela leu ou buscou) aparecem num cartão na própria conversa, tirados da saída do Claude, já que o Chat livre não tem árvore nem Atividade. As respostas aparecem formatadas (títulos, listas, código, links que abrem no navegador), sem nunca virar HTML. As conversas ficam guardadas e o histórico do painel retoma qualquer uma (trocando para a conta dela). A conta e o nível ficam nos ajustes (`freeAccount`, `freeLevel`). O painel da direita (recolhível, aberto por padrão; gaveta por cima em janela estreita) tem a conversa nova, a busca, os projetos (um clique abre) e o histórico agrupado por dia; o medidor de contexto abre a mesma janela dos projetos, com Compactar; e, como nos projetos, um aviso em cima da caixa avisa quando a conversa ficou pesada ou parada há mais de 1 h (a próxima mensagem relê tudo sem o desconto do cache), com Nova com resumo e Compactar. Cada projeto agora tem **terminais de verdade** (aba Terminal no painel de baixo, até 6 por projeto): o shell da pessoa (zsh, bash ou PowerShell) num pseudo-terminal (`portable-pty` no Rust, `xterm.js` na tela; `src-tauri/src/term.rs`, `src/terminal.ts`, `src/termView.ts`, `src/components/ProjectTerminal.tsx`). O `xterm.js` só é baixado quando a aba Terminal aparece, e o shell só abre depois que a tela mede o painel, já com as colunas e linhas certas (sem isso o zsh desenha um `%` solto no primeiro prompt). Cada terminal nasce na pasta do projeto, com o histórico de comandos só daquele projeto (`terms/<projeto>/history` na pasta de dados do app) e com a conta do projeto para o Claude Code (`CLAUDE_CONFIG_DIR`), então `claude` digitado ali usa a mesma conta do chat. No zsh do macOS o `/etc/zshrc` força o `HISTFILE`, por isso o Veocode abre o zsh com um `ZDOTDIR` próprio que carrega a configuração normal da pessoa (`.zshenv`, `.zprofile`, `.zshrc` e `.zlogin` dela) e só no fim troca o histórico. Trocar de projeto ou de tela não fecha nada: cada terminal segue rodando e volta como estava (os últimos 256 KB de saída ficam guardados para redesenhar). Fechar a aba, remover o projeto ou fechar o app encerra o shell. É um terminal normal: nada impede um `cd` para outra pasta; a separação está no ponto de partida, no histórico e na conta, e quem fica presa à pasta é a IA, pelo nível de acesso. Os comandos que a IA roda continuam na aba "Comandos do agente", e o painel de baixo agora muda de altura arrastando a borda de cima. Cada projeto também tem a aba **Git** no painel da direita (`src-tauri/src/git.rs`, `src/git.ts`, `src/components/GitPanel.tsx`), só leitura: branch e upstream com ↑ commits para enviar e ↓ para baixar, mudanças desde o último commit (prontas, alteradas, novas e em conflito; clicar abre no editor), os últimos 40 commits marcando o que só existe neste computador e o que já está no remoto, o que chegou no remoto e ainda não está aqui, branches (com ↑↓, só local ou apagado no remoto), stash, remotos (endereços sem usuário nem token) e aviso de merge ou rebase no meio do caminho. Com o GitHub CLI (`gh`) logado, mostra também o repositório (público/privado, issues, PRs, estrelas, última versão), as últimas execuções do CI no branch e os PRs abertos com review e checks. A única ação é **Buscar** (`git fetch --all --prune`), que não mexe em arquivos nem branches; commit, push e pull ficam com a pessoa ou com a IA. O status relê a cada 8 s com a aba aberta, ao voltar para a janela e depois de mudanças no disco, sempre com `GIT_OPTIONAL_LOCKS=0` para não brigar com o git da pessoa. No Mapa e embaixo do nome do projeto aparece um resumo (↑ ↓ ● mudados). O **Painel** (segundo ícone do menu lateral; `src/views/Board.tsx`, `src/board.ts`, `src/feeds.ts`, `src/components/ChatPane.tsx`) mostra todos os projetos de uma vez e até 4 conversas lado a lado. Em **Todos**, cada projeto vira um cartão com a situação agora (pedindo permissão, trabalhando, com erro ou parado), a última fala da conversa, a conta, o nível de acesso, o git (↑ ↓ ● mudados), os agentes de IA abertos naquela pasta (inclusive o Claude aberto no Terminal ou no editor, achado pelo Raio-X) e os terminais; quem pede permissão vem primeiro, com a borda piscando. Em **Lado a lado**, os projetos escolhidos ocupam os cantos (superior esquerdo, superior direito, inferior esquerdo, inferior direito), cada um com a conversa rolando ao vivo (pedidos, respostas, passos agrupados), a resposta sendo escrita, os cartões de Permitir e Recusar, a caixa para pedir e o botão de parar; dá para trocar o projeto de um canto, mudar de lugar, ocupar a tela toda (Esc volta), abrir o projeto completo e tirar da grade sem parar nada. A grade fica guardada neste computador. Para isso a conversa de cada projeto passou a ser guardada separada (`src/feeds.ts`): os passos do Claude vêm do histórico dele lido num canal próprio (`agent_poll` com `channel: "board"`, para não tirar eventos da tela Projetos), e as falas e os passos das APIs vêm dos eventos do chat; pedidos mandados do Painel não aparecem mais na tela do projeto que estiver aberto. O projeto "demo · simulação" continua mostrando a animação do agente (`src/sim/agentSim.ts`).

O Veocode **não mexe** nos arquivos dos seus projetos por conta própria. As exceções são pedidas por você: o nível de acesso grava `.claude/settings.local.json`, o chat faz o que o nível deixa, e o Inventário pode tirar uma skill ou um MCP que mora na pasta do projeto (com aviso antes). "Remover da lista" só tira a pasta do cadastro (`projects.json` na pasta de configuração do app).

## Rodar

```bash
npm install
npm run tauri dev   # janela nativa (Rust + Tauri)
npm run dev         # só a interface no navegador, em http://localhost:1420 (sem acesso a pastas)
cd src-tauri && cargo test   # testes do lado Rust
```

## Stack

- **Rust + Tauri 2**: backend nativo. Usa o WebView do sistema (WKWebView no macOS, WebView2 no Windows) em vez de embutir um Chromium como o Electron.
- **Windows**: o código compila para Windows (`cargo check --target x86_64-pc-windows-gnu`, sem avisos), mas o app ainda não foi aberto nem testado numa máquina Windows. Só o macOS foi testado de verdade.
- **SolidJS + TypeScript**: interface com reatividade fina e sem DOM virtual. Abre com ~300 KB gzip (dois arquivos: ~200 KB da interface e ~100 KB do estado e das bibliotecas); o `xterm.js` do terminal (~71 KB gzip) só carrega quando a aba Terminal aparece pela primeira vez.
- **Sem bibliotecas de UI**: CSS próprio com tokens em `:root` (fica fácil criar um tema claro depois). Ícones de `lucide-solid`; o terminal usa `xterm.js` e, no Rust, `portable-pty`.
- **Ícone do app**: desenhado em `src-tauri/icons/source/veocode.svg` (a pasta do projeto, o V da marca e os cursores das contas). Depois de mudar o desenho: `rsvg-convert -w 1024 -h 1024 src-tauri/icons/source/veocode.svg -o icon.png && npx tauri icon icon.png -o src-tauri/icons` (gera o `.icns` do macOS, o `.ico` do Windows e os PNG).

## Telas

| Tela | O que mostra |
|---|---|
| Visão geral | Tela de início: o dia em números e gráfico, até 4 conversas ao vivo (arraste para trocar de lugar) e a lista de projetos, com sugestões de pastas onde você já usou o Claude |
| Projetos | Árvore de arquivos, editor, chat com o agente (o nível de acesso fica dentro dele), Git com desenho dos branches, Rastro (sobras para limpar, pastas fora do projeto, instalações e o que a IA consultou), atividade, terminal próprio e cursores; modo Simples/Avançado (coluna com todos os projetos) |
| Contas e IAs | Uso de cada conta e matriz "quem usa o quê" (clique para trocar) |
| Computador → Espaço e memória | (antigo Raio-X) Caches com limpeza, o que cada IA instalou, IAs locais (Ollama, LM Studio, Hugging Face), VMs/containers com o projeto de origem e IAs abertas com onde estão |
| Computador → Extras do Claude | (antigos Inventário e Skills e MCP) Receitas, atalhos, ajudantes, conexões e pacotes: onde valem, quanto pesam, ligar, desligar e tirar, e ler cada receita |
| Chat livre | Conversa sem projeto, que olha o computador quando a pergunta pede; selo de permissão (Leitura por padrão), medidor de contexto e painel da direita com conversa nova, projetos e histórico |
| Ajustes | Tema claro, escuro ou igual ao sistema; estilo dos ícones e das animações, com prévia; onde o app guarda as coisas |
| Gráficos | Uso da semana em frase em cada conta, espaço das IAs ao longo dos dias (Espaço e memória) e passos por hora nas últimas 24 h em cada cartão da Visão geral |
| Sininho (topo) | "Precisa de você": permissões, erros, conflitos, contas sem login, commits só neste computador e disco cheio, cada um levando direto ao lugar certo |

`⌘K` / `Ctrl+K` abre a paleta de comandos. `F1` abre a ajuda.
